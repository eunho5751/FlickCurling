# 온라인 대전 설계 (최종)

## 1. 결정 사항 요약

| 항목 | 결정 |
| --- | --- |
| 네트워크 | NGO(Netcode for GameObjects) + Distributed Authority. 고정 호스트 없음 |
| 매칭 | UGS 매치메이커, 빠른 매칭(랜덤). 같은 계정끼리는 매칭되지 않음 |
| 맵 | 기본 맵만. 경기 정보와 매칭 속성에 맵 ID를 넣어 나중에 맵 선택을 붙일 수 있게 함 |
| 친구 대전 | 나중에 (방 코드 초대) |
| 계산 방식 | 궤적 방식. 쏜 사람 기기만 물리를 계산하고, 두 기기는 같은 기록을 재생 |
| 색 | 각자 자기 화면에서 자기가 흑(왼쪽), 상대가 백(오른쪽) |
| 선후공 정하기 순서 | 서버가 경기 ID로 정함(무작위) |
| 끊김 | 경기 네트워크에서 끊긴 사람이 진다. 재접속 없음. 짧은 백그라운드는 상대 카드로 바로 맞춤 |
| 전적 | 승/패/무. 서버(Cloud Code)가 기록, 경기 중에는 반영 안 됨 |
| 결과 확정 | 첫 보고로 즉시 확정, 두 번째 보고는 비교만(불일치 기록) |
| 경기 정보 보관 | 두 사람 모두 확인하면 삭제, 남은 것은 하루 한 번 정리 |

## 2. 구성

- **세션(Distributed Authority)**: Unity 서비스가 세션을 들고 있고, 두 플레이어가 서비스에 직접 연결한다. 한 사람이 나가도 세션은 남는다. 둘 다 나가면 세션이 닫힌다.
- **경기 상태 오브젝트**: 네트워크에 하나만 둔다. 돌 배치, 엔드, 샷 번호, 해머, 점수표, 티켓, 차례 번호, 마감 시각, 선후공 정하기 상태, 난수 상태, 결과. 돌은 궤적을 재생만 하므로 네트워크 오브젝트가 아니다.
- **권한**: 차례마다 쏘는 사람에게 경기 상태의 권한이 넘어간다. 권한 이동은 차례가 바뀔 때만 일어난다.
- **사람 구분**: 연결 번호가 아니라 UGS 플레이어 ID로 구분한다(다른 기기 접속에도 유지).
- **서버(Cloud Code 모듈)**: 경기 시작, 결과 보고, 확인, 경기 취소(시작 전), 이탈 정리, 경기 조회, 전적 조회, 하루 한 번 정리.
- **Cloud Save**
  - Game Data `matches`(서버 전용): 경기 ID별 경기 정보(두 플레이어, 시작 시각, 상태, 결과, 보고 목록, 불일치, 확인 여부).
  - 플레이어 데이터(플레이어는 읽기만, 서버가 쓰기): 진행 중인 경기 ID, 승·패·무.
  - 플레이어 데이터(서버 전용): 불일치 횟수 등 누적 기록.
  - 상대의 전적은 서버의 전적 조회 함수로 받는다.

## 3. 화면 흐름

1. **메인 메뉴 → "온라인 대전" 팝업** (오프라인 대전 팝업과 같은 형식)
   - 모드: 랜덤 매칭 (나중에 친구와 같이하기 추가)
   - 맵: 기본 (나중에 맵 추가)
   - **확인**을 누르면 매칭 시작. 버튼 글자가 "00:00" 형식의 경과 시간으로 바뀐다.
   - 팝업을 닫거나 그 버튼을 다시 누르면 매칭 취소.
   - 매칭은 취소할 때까지 계속 찾는다(큐의 대기 시간이 끝나면 자동으로 다시 건다).
2. **상대 찾음** → 바로 페이드 아웃하고 게임 씬으로 이동한다. 이때부터는 취소할 수 없다(세션 네트워크가 켜지기 전에 나가면 SDK가 꼬이기 때문). 매칭은 매치메이커 티켓을 직접 만들고 1초마다 확인하며, 취소하면 언제나 티켓을 지우고 끝난다. 짝이 지어지면 매치메이커의 매칭 결과(경기 ID로 조회, 플레이어 권한으로 가능)에서 상대 ID와 닉네임을 바로 알아낸다(닉네임은 각자 티켓의 플레이어 데이터에 넣는다. 전적 패널 표시용). 경기 설정은 경기 ID에서 정하고, 경기 시작은 뒤에서 보낸다. 전적은 각자 검색 시작 때 자기 Cloud Save(protected "stats")에서 읽어 티켓에 닉네임과 함께 넣으므로 매칭 결과에 이미 들어 있다(표시용. 실제 전적은 서버만 갱신). 전적이 없으면 0승 0패 0무로 표시한다. 세션 참가와 네트워크 연결(수 초)은 그 뒤에서 계속한다.
3. **전적 패널**: 위에 상대, 아래에 나, 가운데 VS. 각 카드에 흑/백 돌 이미지, 닉네임, 승·패·무. (그래픽은 게임 스타일로 Codex 제작) 페이드 인 후 바로 뜨고, 연결 중에는 아래에 "상대와 연결하는 중…"이 깜빡인다. 패널은 뜬 순간부터 2.5초를 센다(연결 대기 시간 포함). 그 안에 두 기기가 다 연결되면 2.5초에, 연결이 더 걸리면 둘 다 연결되는 즉시 닫힌다. 두 기기가 같이 닫도록 각자 패널이 뜬 시각과 연결된 시각(네트워크 시간)을 주고받아, 늦게 뜬 패널의 2.5초와 늦게 연결된 시각 중 나중에 닫는다. "연결됨"은 세션 참가, 네트워크, 매치 오브젝트, 상대 카드까지 다 된 것이다(세션의 참가자 목록은 떠난 사람을 늦게 빼서 쓰지 않는다). 두 기기 모두 매칭된 순간부터 GameConfig.connectSeconds(45초) 안에 연결되지 않으면 포기한다(같은 순간부터 세서 함께 포기한다). DA 서비스가 경기 네트워크의 Relay 접속 코드를 로비에 늦게 써 주는 일이 가끔 있어(알려진 서비스 문제, 측정상 보통 수 초, 늦으면 20~35초 이상) 넉넉히 둔다. 그보다 먼저 포기하는 건 확실할 때뿐이다: 상대가 내가 들어간 뒤 GameConfig.opponentJoinSeconds(10초) 안에 세션에 안 나타남, 세션에서 상대가 나감. 연결이 안 되면 경기를 취소하고 메인 메뉴로 돌아가 온라인 대전 팝업에서 바로 다시 찾는다. 연결 중에는 메인 메뉴로 나갈 수 없다.
4. **선후공 정하기** → 엔드 진행 → 결과. 기존 오프라인 흐름과 같다.
5. **게임 결과 화면**: "다시 하기"를 누르면 바로 매칭 시작, 버튼 글자가 "00:00" 경과 시간으로 바뀐다. 다시 누르거나 "메인 메뉴로 이동"을 누르면 매칭 취소. 매칭되면 2번부터 다시.

### 팝업 동기화
- 게임 씬의 팝업(선후공 정하기 시작, 선후공 결과, 엔드 사이 결과)에서 버튼을 누르거나 카운트다운이 끝나 자동으로 눌리면, 버튼을 끄고 "상대를 기다리는 중…"으로 바꾼다. 두 사람이 모두 누르면 진행한다.
- 모든 엔드가 끝난 뒤의 팝업(마지막 엔드 결과, 게임 결과)은 동기화하지 않는다. 각자 진행한다.
- 상대 카드가 없으면(끊김) 기다리지 않는다.

### HUD (시트 위 차례 정보)
- "선후공 정하기" 글자와 기록, 샷 개수 "5 / 8"은 없앤다.
- 왼쪽 반은 나(흑), 오른쪽 반은 상대(백). 가운데 위부터 아래로:
  1. 흑/백 돌 이미지 + 닉네임 (예전 샷 개수 글자 크기, 길면 반쪽 폭에 맞게 줄어듦)
  2. 승 / 패 / 무 전적
  3. 선공/후공 + 남은 알 (선후공 정하기 중에는 표시하지 않음)
- 오프라인도 같은 배치를 쓴다.
  - AI 대전: 왼쪽은 내 닉네임, 오른쪽은 "AI". 전적은 표시하지 않음.
  - 2인 대전: "플레이어 1", "플레이어 2". 전적은 표시하지 않음.
- AI 관전 모드는 없앤다.

## 4. 한 샷의 흐름 (궤적 방식)

1. **차례 시작**: 쏠 사람에게 권한이 넘어가고, 경기 상태에 차례 번호와 마감 시각(서버 시각)이 기록된다. 양쪽 심지가 같은 마감 시각 기준으로 탄다.
2. **입력 확정**: 손을 떼는 순간, 계산보다 먼저 입력(방향, 세기)을 상대에게 보낸다. 이 순간 샷이 확정된다.
3. **계산**: 쏜 사람 기기가 돌이 멈출 때까지 한 번에 계산하고 기록한다. 움직인 돌의 위치(6스텝마다, 0.01 단위), 충돌·벽·범퍼·탈락 이벤트, 멈춘 순간의 경기 상태. 한 샷 기록은 보통 1KB 이하.
4. **전송**: 기록을 보내고 경기 상태를 즉시 확정한다.
5. **재생**: 두 기기 모두 같은 기록을 재생한다(소리·이펙트는 이벤트 시점에). 재생 시작 시각(네트워크 시간)을 함께 보내서, 늦게 받은 쪽은 조금 빠르게 재생해 따라잡는다(6장). 끝나면 기록된 경기 상태를 그대로 적용하므로 기기 간 부동소수점 차이와 무관하게 결과가 같다.
6. **다음 차례**: 두 사람의 "재생 끝" 신호가 모두 오면 즉시, 늦어도 내 재생이 끝난 뒤 3초에 시작. 상대 카드가 없으면(끊김) 기다리지 않는다.

- **마감은 네트워크 시간으로 공유**한다. 네트워크 시간은 NGO의 ServerTime(DA 서비스가 기준인 세션 시계, 두 기기가 같고 폰 시계와 무관)이다. 쏠 사람 기기가 차례를 시작할 때 마감을 정해 상대에게 보내고(Deadline 메시지), 두 기기 모두 그 마감으로 심지를 그리고 판정한다. 앱이 백그라운드에서 멈춰 있던 시간도 탄 것으로 친다.
- 시간 초과: 쏠 사람은 마감이 지나면 스스로 보이드를 보낸다. 기다리는 쪽은 마감 3초 뒤에도 아무것도 오지 않으면 보이드로 판정한다.
- 입력은 받았는데 궤적이 8초 넘게 오지 않으면 받은 입력으로 직접 계산한다.
- **같은 차례 다시 하기는 어떤 경우에도 없다.** 입력이 확정된 뒤 쏜 사람이 끊기면, 상대가 그 입력으로 계산해 결과를 확정한다.

## 5. 결과와 전적

1. **경기 시작**: 매칭 후 각자 서버의 "경기 시작"을 호출한다. 서버는 경기 정보를 만들고(이미 있으면 그대로), 각 플레이어 데이터에 진행 중인 경기 ID를 적는다. 선후공 정하기 순서와 난수 씨드는 경기 ID에서 정해서 두 호출이 같은 값을 쓴다. 기기도 같은 계산(경기 ID의 해시)으로 이 값을 바로 정해서, 서버 응답을 기다리지 않고 게임을 시작한다. 경기 시작과 전적 조회는 뒤에서 보내고, 전적은 도착하는 대로 전적 패널과 시트에 채운다. 경기 기록이 있어야 하는 호출(시작 표시, 결과 보고, 취소, 확인)은 경기 시작 호출이 끝난 뒤에 보낸다.
2. **결과 보고**: 마지막 샷의 결과로 경기가 끝나는 그 순간(결과 화면을 띄우기 전에), 그때 접속해 있는 사람이 결과(승자 또는 무승부, 최종 점수)를 보고한다.
   - 첫 보고: 즉시 확정, 두 사람의 승·패·무를 한 번 올린다.
   - 두 번째 보고: 확정된 결과와 비교만 하고, 다르면 경기 정보와 보낸 사람의 누적 기록에 불일치를 남긴다. 전적은 바뀌지 않는다.
   - 동시에 들어온 보고는 버전 확인으로 하나만 확정된다.
   - 한 사람만 끝까지 있었다면 보고도 하나뿐이라 불일치는 확인할 수 없다.
3. **확인**: 결과 화면을 본 사람은 서버에 확인을 보내고 자기 진행 중인 경기 ID를 지운다. 두 사람 모두 확인하면 경기 정보를 삭제한다.
4. **앱을 다시 켠 사람** (앱 실행·로그인 직후): 서버에 진행 중인 경기가 남아 있으면 진 것으로 정리한다. 시작 전이면 취소, 시작됐으면 상대 승으로 보고, 그다음 확인. 이미 끝났거나 없으면 확인만 한다. 경기로 돌아가지 않는다.
   - "시작됨": 두 기기가 서로의 도착 신호를 받으면 서버에 알린다(MarkStarted). 경기 기록의 Started가 이 값이다.
5. **하루 한 번 정리** (Scheduler + Trigger → Cloud Code):
   - 종료된 지 7일 지난 경기 정보 삭제.
   - 시작한 지 2시간이 지났는데 진행 중으로 남은 경기(둘 다 끊기고 아무도 보고하지 못한 경우) → 둘 다 패로 확정 후 삭제.
   - 시작되지 않은 채 남은 경기(취소 호출 실패 등) → 패 없이 삭제.

## 6. 끊김

원칙은 하나다. **경기 네트워크에서 끊긴 사람이 진다.** 재접속, 앱을 다시 켜서 경기로 돌아가기는 없다.

- **끊김 판정은 DA 서비스가 한다.** 각 기기는 세션에 자기 "카드"(OnlinePlayerState, NGO 네트워크 오브젝트, 자기 소유)를 하나 두는데, 기기가 응답하지 않으면 서비스가 약 10초 뒤(측정 11초) 그 기기를 네트워크에서 내보내고 카드도 지운다. 우리가 따로 신호(하트비트)를 주고받지 않는다.
  - 내 연결은 살아 있는데 상대 카드가 사라짐(한 번 본 뒤) → 상대가 끊김 → 서버에 내 승리를 보고하고 "상대 연결이 끊겨 기권승" 결과 카드.
  - 내 네트워크가 끊김 → 내가 끊김 → 서버에 상대 승리를 보고하고 "연결이 끊겨 기권패 처리됐어요" 결과 카드.
  - 경기 시작 전(서로 도착 전)이면 끊김은 노쇼와 같다: 경기 취소, 다시 찾기.
- **기권**: 경기가 시작된 뒤 설정의 [메인 메뉴로 이동]은 확인 후 기권패로 처리한다(상대에게 즉시 알리고 서버에 상대 승으로 보고). 상대 화면에는 "상대가 기권했어요" 결과 카드가 뜬다.
- **짧은 백그라운드**(서비스가 끊기 전): 연결이 살아 있어서 경기는 이어진다. 돌아온 순간 그사이 일을 재생하지 않고, 상대 카드의 경기 상태로 바로 맞춘다.
  - 카드에는 안정 시점(차례 시작, 팝업)마다 경기 상태, 턴 마감, 적은 시각(네트워크 시간)이 적히고, 샷이 시작되면 그 샷(입력, 궤적 기록, 재생 시작 시각)도 적힌다.
  - 돌아오면 화면을 딤하고 가운데에 "경기로 돌아가는 중…"을 띄운 채 2초 동안, 상대 카드가 내 마지막 상태보다 나중에 적혔고 내용이 다르면 그 상태로 맞춘다(그 사이 늦게 들어온 갱신도 다시 맞춘다). 진행 중인 샷이 있으면 상대 화면과 같은 지점(지금 시각 - 재생 시작 시각)으로 바로 건너뛴다.
  - 마감은 네트워크 시간이라 백그라운드에 있던 시간도 탄 것으로 친다.
- **샷 재생은 두 기기가 같은 시각 기준**이다. 쏜 사람은 바로 재생하고 재생 시작 시각을 샷과 함께 보낸다. 받는 쪽은 받은 순간 처음부터 재생하되, 늦은 만큼 GameConfig.catchUpSpeed(기본 1.15배)로 빠르게 돌려 따라잡은 뒤 원래 속도로 돌아온다. 남은 재생 시간 안에 다 못 따라잡을 만큼 늦었으면 그 부분만 먼저 건너뛴다.
- **앱을 다시 켰을 때** 서버에 진행 중인 경기가 남아 있으면(앱이 꺼진 경기) 진 것으로 정리한다: 시작 전이면 취소, 시작됐으면 상대 승으로 보고한 뒤 확인을 보낸다. 경기로 돌아가지 않는다.
- 같은 계정이 다른 기기로 접속하면 이전 기기는 경기에서 바로 나가고(진 것과 같다) "다른 기기에서 로그인했어요" 팝업을 띄운다.
- 기기 쪽 전송 끊김 판정(UnityTransport DisconnectTimeoutMS)은 10초로 설정했다. 다만 서비스가 이미 내보낸 기기가 그걸 알기까지는 측정상 최대 약 30초 걸렸다(서버가 끊김을 알려 주면 0.5~2초).
- 세션을 나갈 때마다 콘솔에 `[Multiplayer]: GameObjectsNetcodeNetworkHandler.StopAsync: Failed to stop session: session was never started.` 경고가 뜬다. SDK 내부의 이중 정리 때문이고(SessionHandler.LeaveAsync가 네트워크를 정리한 뒤 RemovedFromSession을 내고, SessionManager.OnRemovedFromSession이 같은 정리를 한 번 더 한다) 기능 영향이 없어 무시한다. 우리 코드에서는 피할 수 없다(Multiplayer Services 2.4.1 기준).

### 상황별 처리

| 언제 | 누가 끊김 | 처리 | 전적 |
| --- | --- | --- | --- |
| 매칭 대기 중 | 나 | 매칭 취소, 다시 매칭 | - |
| 매칭 직후, 연결 중(전적 패널) | 한쪽 | 매칭 후 GameConfig.connectSeconds(45초) 안에 연결 안 됨(두 기기 같이 포기), 상대가 GameConfig.opponentJoinSeconds 안에 세션에 안 옴, 상대가 세션을 나감 → 경기 취소, 메뉴에서 다시 찾기 | 없음 |
| 연결 후, 서로 도착 전 | 한쪽 | 20초 안에 상대 도착 신호가 없거나, 어느 쪽이든 끊김 → 경기 취소(생성 후 90초 이내), 다시 찾기 | 없음 |

| 짧은 백그라운드 | 나 | 이어감, 돌아오면 상대 카드로 바로 맞춤 | - |
| 메뉴로 나가기 | 나 | 기권패 | 정상 기록 |
| 앱 종료 후 다시 켬 | 나 | 경기로 돌아가지 않음, 진 것으로 정리 | 패 |
| 같은 계정으로 다른 기기 접속 | - | 마지막으로 로그인한 기기만 남는다(ClaimDevice + 푸시). 이전 기기는 경기 중이면 나가고(패), "다른 기기에서 로그인했어요" 팝업. [다시 접속]을 누르면 이 기기가 다시 등록된다 | 패 |

## 7. 보류 (나중에)

- **끊었다 붙었다 반복 막기**: 경기당 합산 끊김 시간·횟수 제한, 계정별 이탈 기록으로 경고·매칭 불이익.
- **가짜 궤적 걸러내기**: 받는 쪽이 같은 입력으로 다시 계산해 비교, 최대 속도·순간이동 같은 상식 검사.
- **결과 조작 막기**: 랭크나 보상이 붙으면, 샷 입력을 서버에 쌓고 경기 끝에 Cloud Code가 다시 계산해 승패를 정한다(그때는 첫 보고 확정 대신 서버 계산이 정답).
- **이상 탐지·제재**: 불일치 횟수 등 누적 기록으로 의심 계정 조회.
- 친구 대전, 맵 선택, 상대 조준 미리보기.

## 8. 준비해야 할 것 (대시보드·배포)

- UGS 매치메이커 큐(1:1 빠른 매칭) 배포
- Cloud Code 모듈 배포
- Scheduler + Trigger(하루 한 번 정리) 배포
- Multiplayer(Distributed Authority) 사용 설정 확인

배포용 설정 파일은 프로젝트에 두고, 에디터의 Deployment 창에서 배포한다.
